# Doc's Digital Consulting

The website for Doc's Digital Consulting, an AI and automation consulting and full-stack web development practice for small businesses. It covers six services (AI & automation consulting, full-stack web development, AI search optimization with GEO, AEO, and SEO, Google Ads, social media, and analytics dashboards), a 38-post blog, a Book a Call form, and 12 free lead magnet landing pages. Every page carries connected JSON-LD (Organization, WebSite, WebPage, plus BreadcrumbList, FAQPage, Service, Person, BlogPosting, or ItemList where they apply), generated by `BaseLayout` so new pages get it automatically.

**Live site:** https://week5-astro.vercel.app

Built with [Astro 7](https://docs.astro.build) (TypeScript strict) and React and Preact islands. Deployed as a static site on Vercel.

## Commands

Run these from the project root. The site needs Node 24.

| Command           | What it does                                                   |
| :---------------- | :------------------------------------------------------------- |
| `npm install`     | Install dependencies                                           |
| `npm run dev`     | Start the dev server at `localhost:4321`                       |
| `npm run build`   | Build the site to `./dist/`                                    |
| `npm run preview` | Serve the built site locally                                   |

Search only works after `npm run build`, because the index is created from the built pages.

## Islands and how they load

Most of the site is plain HTML with no JavaScript. Only the interactive parts below ship JavaScript, and each one loads when it's needed.

| Island                     | Where                 | Framework | Directive      | What it does                                         |
| :------------------------- | :-------------------- | :-------- | :------------- | :--------------------------------------------------- |
| `BookCallForm`             | `/book-a-call`        | React     | `client:load`    | Lead form with validation                            |
| `LeadMagnetForm`           | `/lp/...` pages       | React     | `client:load`    | Email signup for a free download                     |
| `BlogBrowser`              | `/blog`               | React     | `client:idle`    | Category filter and search over the post cards       |
| `ListenPlayer`             | Every blog post       | React     | `client:idle`    | "Listen to this post" text-to-speech player          |
| `MarketingCheckup`         | Homepage hero         | Preact    | `client:visible` | 60-second marketing checkup with a live score ring and next steps |
| `RoiCalculator`            | Homepage              | Preact    | `client:visible` | Estimates return on ad spend                         |
| `AutomationDemo`           | `/ai-and-automation-consulting` | Preact | `client:visible` | "Watch an AI helper work": plumber, bakery, law firm |
| `DashboardDemo`            | `/marketing-analytics-and-dashboards` | Preact | `client:visible` | Sample dashboard (law firm or shop, 30/90 days) with a table view |
| `AiAnswerDemo`             | `/ai-search-optimization` | Preact | `client:visible` | What an AI assistant says before and after GEO/AEO |
| `PlatformPicker`           | `/website-development-and-management` | Preact | `client:visible` | Four questions that suggest a website platform |
| `SearchTermSorter`         | `/paid-search`        | Preact    | `client:visible` | "Block or keep" game for Google Ads search terms     |
| `PostWeekDemo`             | `/social-media-marketing` | Preact | `client:visible` | A week of sample posts in a phone frame              |

The service demos sit in each service page's hero in place of a stock photo (on the AI & Automation page, just below it). Each renders complete HTML on the server, so nothing shifts when it hydrates and it still reads correctly without JavaScript. All sample data is labeled "Illustrative example." Animations respect `prefers-reduced-motion`. The AI & Automation page's hero text-message animation (`src/components/MissedCallDemo.astro`) is pure CSS (no island), with a pause button to meet WCAG 2.2.2. That page uses the shared split hero (`src/components/Hero.astro`) and shows its demo in a section below it.

Island source files are in `src/components/islands/react/` and `src/components/islands/preact/`.

### Why each directive

- **`client:load` (right away): the two forms.** On `/book-a-call` and the landing pages, the form is the reason the page exists. People often start typing within a second or two, so the validation, error messages and success state have to work as soon as the page opens. Both forms also use `method="post"`, so a submit that happens before JavaScript loads can never put an email address in the URL.
- **`client:idle` (once the browser is free): blog filter, listen player.** None of these are needed to read the page, and the page is already fully readable without them. The blog index renders all 38 post cards as static HTML, and the filter only hides and shows them. Waiting for idle keeps their JavaScript out of the way of the first paint.
- **`client:visible` (when scrolled into view): ROI calculator and the service demos.** The ROI calculator sits below the fold on the homepage, and many visitors never scroll that far. Its code only downloads when it comes into view. The service demos are in view right away on desktop, so they hydrate almost immediately there, but on phones they sit below the intro and wait until scrolled to. All of these are Preact instead of React because Preact is much smaller.

To see the difference: open DevTools → Network and load `/book-a-call`. The form's script loads right away. On the homepage, `RoiCalculator` doesn't load until you scroll down to it.

## Forms

Both forms share the same validation and error handling (`src/lib/lead.ts`). An empty submit shows an error next to each field that needs one and moves focus to the first one. A valid submit shows a success message.

The forms send through [Formspree](https://formspree.io). The endpoint is set as the default for `PUBLIC_FORMSPREE_ENDPOINT` in `astro.config.mjs`. It isn't a secret (the browser needs it to send the form), so it doesn't need to be set in Vercel. Setting that variable overrides it. Landing pages still show a placeholder in place of the download link.

Without an endpoint, the forms run in **demo mode**: nothing is sent, and you can test failures with `?simulate=` in the URL (the values are in `SIMULATIONS` in `src/lib/lead.ts`).

## Third-party script audit

**No third-party scripts load on any page.** The built HTML has no external `<script>` tags, no iframes, no analytics, no ad tags and no tracking pixels. Every script comes from this site's own domain.

| Item | What it's used for | Decision | Why |
| :--- | :--- | :--- | :--- |
| Google Analytics, Tag Manager, Meta Pixel | Tracking | **Removed** (never added) | The site doesn't need tracking yet. These are often the slowest scripts on a small-business site, and they would need a cookie notice. If analytics are added later, use a lightweight, cookie-free tool that loads with `defer`. |
| Google Fonts and other web font hosts | Fonts | **Removed** (never added) | The site uses system fonts, so there's no font download and no extra connection. |
| Embedded video, maps and social widgets | Media | **Removed** (never added) | Each embed loads a large third-party script. Link out instead. |
| picsum.photos | Placeholder photos | **Kept, at build time only** | `<Image>` from `astro:assets` downloads each photo during the build and turns it into small, resized WebP files on this site. Visitors' browsers never contact picsum. The only picsum URLs left are the `og:image` tags, which social sites fetch when a link is shared. These are placeholders until real photos replace them. |
| Astro `ClientRouter` (view transitions and link prefetch) | Smooth page changes | **Kept** | First-party and small. With `ClientRouter`, Astro prefetches every same-site link using the `hover` strategy: a page is fetched only when a visitor hovers over or focuses its link, never on page load. |
| React and Preact runtimes | Islands | **Kept, deferred** | First-party. Loaded only on pages that have an island, and only when that island's directive fires (see above). |
| Formspree | Form submissions | **Kept for later, no script** | When it's connected, the forms send a `fetch` to Formspree only on submit. There's no Formspree script on the page. |

How to check this yourself: run `npm run build`, then search `dist/` for `<script src="http`. There are no matches.

## Performance

- Images: every photo goes through `astro:assets` `<Image>` (WebP at quality 60, with responsive `srcset`/`sizes`). The image that's largest on screen loads with `priority`.
- CSS: inlined into each page (`build.inlineStylesheets: 'always'`), so the first paint doesn't wait on stylesheet requests.
- Fonts: system fonts only, so there's nothing to download.

Lighthouse (mobile) on the live site scores 100 for Performance on the homepage, `/about` and `/blog`.

## Before launch: details to fill in

The site never invents clients, testimonials or results, and no placeholder text appears on any page. These are hidden until they're filled in:

- `CONTACT_EMAIL` and `SOCIAL_LINKS` in `src/consts.ts` (the "Prefer email?" line and the footer's Follow column appear once set), and `OWNER_NAME` (currently "Doc")
- The lead magnet download files (`file` in each `src/content/services/*.yaml`). Until a real URL is set, the success message says the file will be emailed.
- A real headshot for the blog author box (a monogram badge stands in)
- The blog post photos and `og:image` share images, which are still placeholder photos from picsum.photos
